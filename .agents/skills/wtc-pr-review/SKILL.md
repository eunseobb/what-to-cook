# What To Cook PR 코드 리뷰

## 검토 범위와 근거

- PR 번호나 링크가 있으면 해당 PR을 검토한다. 저장소의 PR을 모두 봐 달라는 요청은 열린 PR 전체를 뜻한다. 현재 저장소의 `origin`과 GitHub의 PR 목록을 대조한다.
- 각 PR의 최신 head SHA와 실제 base 브랜치를 확인한다. 선행 기능 위에 쌓인 PR은 그 base와 비교한다. 로컬 Git으로 볼 때는 SHA가 GitHub와 일치하는지 확인하고, 세 점 diff로 PR 범위를 읽는다.
- 변경 코드와 호출부, API 계약, 기존 테스트를 대조해 해당 변경에서 발생하는 버그와 회귀를 찾는다. 발견마다 발생 조건, 사용자 영향, 수정 방향을 짧게 적는다. 실행한 검증과 정적 검토를 구분한다.

## GitHub 인라인 코멘트

- 리뷰 요청만 받은 경우 결과를 채팅에 정리한다. GitHub에 댓글을 달아 달라는 요청이 있으면 게시한다.
- GitHub 커넥터의 `github_add_review_to_pr`를 우선 사용한다. 커넥터로 처리할 수 없으면 GitHub CLI의 리뷰 API를 사용한다. PR마다 `COMMENT` 리뷰 하나에 인라인 코멘트를 묶어 제출한다. 승인이나 변경 요청 상태는 사용자가 지정한 경우에만 사용한다. PR을 머지하지 않는다.
- 각 항목을 현재 PR diff의 관련 줄에 고정한다. 새 코드라면 파일의 저장소 상대 경로, 최신 head SHA, 새 파일 기준 줄 번호와 `RIGHT`를 사용한다. 해당 줄이 diff에 없으면 문제를 유발한 변경 줄을 다시 찾는다. 게시 전에 head가 바뀌었으면 변경과 줄 번호를 다시 검토한다.
- 모든 인라인 코멘트의 첫 줄을 `**Codex 자동 코드 리뷰**`로 시작한다. 빈 줄 다음에 우선순위와 발견 내용을 쓴다. 리뷰 요약에도 Codex가 작성했다고 표시한다. GitHub 작성자란은 인증된 게시 계정으로 표시되며, 이미 게시된 코멘트의 작성자 계정을 바꿀 수 없다.
- 기존 코멘트에 작성 표시를 추가할 때는 리뷰 스레드에서 파일, 줄, 본문을 대조해 Codex가 게시한 항목의 ID를 찾는다. 해당 코멘트의 본문을 제자리에서 편집하고, 이미 표시가 있으면 건너뛴다.
- 게시나 편집이 성공했는지 확인한다. 요청이 타임아웃되거나 결과가 모호하면 기존 리뷰와 스레드를 먼저 조회해 중복 게시를 피한다. 완료 답변에 PR별 리뷰 링크, 게시한 코멘트 수, 실패한 항목을 적는다.

## 1시간마다 열린 PR 검토

- 사용자가 반복 실행을 설정해 달라고 하면 Codex Automations에서 이 저장소를 대상으로 1시간마다 실행되는 독립 작업을 하나 만든다. 같은 목적의 예약이 있으면 갱신한다. 예약 프롬프트에 이 스킬, 저장소, 인라인 게시 권한, 실행 간 상태를 보관할 로컬 파일 경로를 명시한다.
- 매 실행에서 열린 PR의 실제 base와 최신 head SHA를 조회한다. 이전에 검토를 완료한 기록이 없는 PR, 새 커밋이나 강제 푸시로 head가 바뀐 PR, 대상 브랜치가 변경된 PR을 검토한다. 첫 실행은 열린 PR을 기준으로 시작하되, 해당 버전에 대한 기존 Codex 리뷰를 확인해 중복 게시를 피한다.
- 실행 간 상태는 PR 번호별로 대상 브랜치와 마지막으로 완료한 head SHA를 기록한다. 같은 버전의 PR은 건너뛴다. 이전 head와 비교할 수 있으면 그 이후 변경에 집중하되 현재 PR diff와 호출부도 확인한다. 첫 리뷰나 커밋 이력이 재작성된 경우 현재 PR diff를 검토한다.
- 새로 발견한 문제를 현재 diff의 줄에 인라인으로 게시한다. 기존 Codex 스레드를 읽어 같은 문제를 다시 게시하지 않는다. 예약 프롬프트에 게시 권한이 명시된 경우 이 스킬의 GitHub 인라인 코멘트 절차를 따른다.
- 발견 사항이 없으면 GitHub 게시 없이 완료 상태를 기록한다. 발견 사항이 있으면 게시 성공을 확인한 뒤에만 완료 상태를 기록한다. 게시 직전 최신 head와 대상 브랜치를 다시 확인하고, 바뀌었거나 확인에 실패하면 해당 버전을 완료로 기록하지 않는다. 게시 결과가 모호하면 다음 시도 전에 기존 리뷰를 확인한다.
- 새 검토 대상이 없거나 검토 결과 새 발견이 없으면 사용자에게 별도 알림을 보내지 않는다. 새 코멘트를 게시했거나 권한·접속 문제로 실행이 실패했을 때만 결과를 알린다.
